# llminfer Architecture and Milestones

> Learning project: rewrite a pure-Go LLM inference engine from scratch.
> Goal: load GGUF model files (qwen2.5-0.5b) directly and generate text token by token.

## In One Sentence

A pure-Go engine that runs a trained large model. Compared with the plain PyTorch code in the study notes, this is an inference implementation with no framework in between—every byte is handled by ourselves.

## Why Write It From Scratch

- The study notes (learn-llm) use PyTorch, which manages shapes automatically and hides many details.
- Inference frameworks built on top of PyTorch are too engineering-oriented: buffer reuse, quantization, and SIMD are all optimization noise (necessary engineering, but not the main thing to learn).
- This project sits in between: **algorithmically correct, plainly implemented** (get it right first, worry about speed later), with every gear built separately so we can see how it meshes.

## End-to-End Inference Pipeline (What This Project Does in One Pass)

```
Input "Hello"
  ↓
Encode (BPE tokenize) → [token_ids]
  ↓
Forward Prefill (consume the whole prompt at once)
  ↓
24 layers × [RMSNorm → QKV projection → RoPE → GQA attention(write KV) → WO→residual → SwiGLU FFN]
  ↓
Output logits [151936] (score for each candidate token)
  ↓
Sample (temperature + top-k + top-p → pick one token id)
  ↓
Decode (token id → text)
  ↓
Forward single token (KV Cache accumulates history automatically)
  ↓
... loop until EOS or reaching the limit
```

| Package | What it does | Key types |

| `chat` | ChatML conversation template: detection + rendering + default system extraction | `Template`, `Message` |

## How We Verify

- Per-operator correctness relies on `go test` unit tests (tensor/chat/sampler), with values cross-checked against hand-computed samples.
- End-to-end relies on `go run . run <model> "<prompt>"` and checking whether the generation is coherent and sensible.
- Acceptance details and pitfalls for each milestone are recorded in `1-docs/M{n}-*.md`.

## Pitfalls Hit Across M1-M6 (Lessons Learned)

| Milestone | Pitfall | Root cause | Fix |
|---|---|---|---|
| M1 | GGUF tensor offset read incorrectly | offset is relative to the data-region start, not the file header | `DataStart + Offset` |
| M3 | Q6_K dequantization values wrong | wrong sub-block index subscript | Cross-checked the ggml dequantization formula line by line |
| M4 | logits all zeros | 1-D weights (norm) have NE[1]=0, so the AsFloat32 loop runs 0 times → w all zero | Added a `Rows()` method; treat 1-D as 1 row |
| M5 | flag arguments ignored | Go flags must come before positional arguments | `llminfer run -temp 0.8 MODEL "prompt"` |
| M6 | default system extraction fails | the template `\n` is the literal two characters, plus an entire single-quoted block | Strip markers with regex, then strip the literal `\n` |

## Next Steps

The M1–M6 main line is complete. Current main line: **M7 performance optimization** (fused dequantization dot product + multithreading + buffer reuse); see [M7-性能优化方案.md](M7-性能优化方案.md) for details.

Other candidate directions:

- **Incremental continuation**: reuse the KV cache across turns in multi-turn conversation, forwarding only the newly added tokens (currently every turn does a full prefill).
- **More complete templates**: support more templates beyond LLaMA3 and a tools branch (currently only keyword detection + ChatML/LLaMA3 rendering).
